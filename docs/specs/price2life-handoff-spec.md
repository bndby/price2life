# Price to Life (price2life) — Hand-off Specification

## 1. Problem Statement (Постановка проблемы)

Людям сложно соотносить абстрактные денежные ценники товаров и услуг с реальной стоимостью своей жизни и затраченным трудом. Когда человек видит цену в 25 000 ₽ или 120 000 ₽, ему тяжело интуитивно оценить, стоит ли покупка тех рабочих дней, недель или месяцев, которые он потратит на её заработок. Отсутствие простого, приватного и моментального инструмента перевода цен в единицы рабочего времени («X дней и Y часов жизни») приводит к импульсивным и нерациональным тратам.

## 2. Solution (Решение)

Мобильное приложение для Android **«Price to Life»** на React Native (Expo bare workflow / CNG) с компонентами Material Design 3 (React Native Paper).
Приложение решает задачу в два экрана:
1. **Экран настроек (Settings Modal)**: пользователь сохраняет свой персональный чистый доход («на руки», Net) и выбирает расчетный период (в час, день, неделю, месяц или год). При первом запуске приложение принудительно открывает этот экран для калибровки. Данные хранятся строго локально на устройстве в `AsyncStorage`.
2. **Экран конвертера (Converter Screen)**: пользователь вводит цену товара/услуги и мгновенно видит эквивалент рабочего времени жизни в понятной иерархической форме («3 дн. 5 ч.») вместе с общим числом рабочих часов («29 рабочих часов»). Часовая ставка на этом экране не показывается.

## 3. User Stories (Пользовательские сценарии)

1. **As a** новый пользователь, **I want** при первом запуске приложения сразу попасть на экран ввода моего дохода, **so that** мне не приходилось искать, где задать начальные параметры.
2. **As a** новый пользователь, **I want** видеть понятное приветствие и объяснение, зачем указывать доход, **so that** я чувствовал прозрачность и безопасность приложения.
3. **As a** пользователь, **I want** иметь возможность ввести свой доход за любой удобный период (час, день, неделю, месяц, год), **so that** мне не приходилось производить самостоятельные расчеты часовой ставки.
4. **As a** пользователь, **I want** вводить только целые положительные числа дохода, **so that** интерфейс был защищен от опечаток и дробных значений.
5. **As a** пользователь, **I want** видеть расчетную часовую ставку прямо на экране настроек до нажатия «Сохранить», **so that** я мог проверить корректность введенных данных.
6. **As a** пользователь, **I want** блокировку выхода с экрана первого запуска без сохранения дохода, **so that** конвертер не открывался в неработоспособном состоянии.
7. **As a** пользователь, **I want** перехват аппаратной кнопки «Назад» на Android при первом запуске, **so that** случайное нажатие не закрывало ненастроенное приложение.
8. **As a** пользователь, **I want** сохранять настройки локально в надежное хранилище устройства, **so that** при повторных запусках доход не приходилось вводить заново.
9. **As a** пользователь, **I want** открывать экран конвертера после сохранения настроек, **so that** я мог сразу приступить к оценке покупок.
10. **As a** пользователь, **I want** видеть в шапке экрана конвертера кнопку перехода в настройки, **so that** я мог изменить уровень дохода при повышении зарплаты или смене работы.
11. **As a** пользователь, **I want** вводить цену покупки в целых числах с цифровой клавиатуры, **so that** ввод происходил максимально быстро в магазине или браузере.
12. **As a** пользователь, **I want** мгновенно очищать поле цены в один тап по иконке крестика, **so that** не стирать цифры по одной клавишей Backspace.
13. **As a** пользователь, **I want** не видеть часовую ставку на экране конвертера, **so that** уровень дохода не читался с главного экрана посторонним взглядом. Превью ставки остаётся только в настройках.
14. **As a** пользователь, **I want** видеть результат перевода в виде понятной композиции (годы, месяцы, дни, часы), **so that** легко осознавать масштаб покупки относительно стандартного рабочего графика.
15. **As a** пользователь, **I want** видеть общее количество рабочих часов с корректным грамматическим склонением («1 рабочий час», «2 рабочих часа», «29 рабочих часов»), **so that** интерфейс выглядел качественно на русском языке.
16. **As a** пользователь, **I want** при цене покупки менее 30 минут работы видеть отметку «< 1 ч.», **so that** мелкие траты (кофе, проезд) не отображались сбивающим с толку нулем.
17. **As a** пользователь, **I want** при нулевой цене видеть четкий результат «0 ч.», **so that** не возникало ошибок валидации или неопределенности.
18. **As a** пользователь, **I want** автоматическое скрытие клавиатуры при касании любой свободной области экрана, **so that** карточка с результатом не перекрывалась клавиатурой.
19. **As a** пользователь, **I want** автоматический пересчет результата конвертера при изменении дохода в настройках, **so that** мне не требовалось повторно вводить цену.
20. **As a** пользователь, **I want** адаптацию верстки под системный статус-бар и вырезы Android-смартфонов, **so that** элементы управления не наезжали на системные индикаторы.

## 4. Implementation Decisions (Решения по реализации)

### 4.1. Архитектура проекта и стек технологий
- **Фреймворк**: React Native 0.86.3 в рамках Expo SDK 57 (шаблон `bare-minimum` / Continuous Native Generation — CNG).
- **Платформа**: Android (compileSdk 36, targetSdk 36, JDK 17, NDK 27.1).
- **Язык**: TypeScript с поддержкой строгой типизации.
- **UI Kit**: React Native Paper 5.15.3 (Material Design 3 компоненты: `Appbar`, `Card`, `TextInput`, `SegmentedButtons`, `Surface`, `Text`, `HelperText`, `Button`).
- **Навигация**: `@react-navigation/native-stack` 7.x (`react-native-screens`, `react-native-safe-area-context`).
- **Персистентность**: `@react-native-async-storage/async-storage` 2.2.0 (через `npx expo install`).

### 4.2. Модель предметной области (Domain Model)
Сформулирована в `CONTEXT.md`:
- `Income`: целое положительное число (Net, «на руки»).
- `IncomePeriod`: `'hour' | 'day' | 'week' | 'month' | 'year'`.
- `WorkSchedule`: фиксированный рабочий календарь (8 ч/день, 40 ч/неделю, 2080 ч/год, 173.33 ч/месяц).
- `HourlyRate`: ставка одного рабочего часа пользователя.
- `ItemPrice`: стоимость товара/услуги (целое неотрицательное число).
- `LifeTimeEquivalent`: декомпозиция на годы, месяцы, дни, часы.

### 4.3. Чистый вычислительный модуль (`src/core/calculator.ts`)
*Утвержден и верифицирован прототипом на ветке `prototype/conversion-calculator`.*

```typescript
export interface WorkScheduleConfig {
  readonly hoursPerDay: number;   // 8
  readonly hoursPerWeek: number;  // 40
  readonly hoursPerYear: number;  // 2080
  readonly hoursPerMonth: number; // 173.33
}

export function calculateHourlyRate(
  income: number,
  period: IncomePeriod,
  schedule: WorkScheduleConfig = DEFAULT_WORK_SCHEDULE
): number;

export function calculateLifeTime(
  price: number,
  hourlyRate: number,
  options?: ConversionOptions,
  schedule?: WorkScheduleConfig
): ConversionResult;
```
- **Защита округления**: если остаток округленных часов достигает `hours >= 8`, происходит перенос в дни (`days += 1; hours = 0`). Если `months >= 12`, происходит перенос в годы (`years += 1; months %= 12`).
- **Микропокупки**: при `years === 0 && months === 0 && days === 0 && hours === 0 && price > 0` возвращается `< 1 ч.` и `< 1 рабочего часа`.
- **Плюрализация**: русские окончания для 1, 2-4, 5-20 и десятков с форматированием пробелов тысяч.

### 4.4. Хранилище и стейт (`src/storage/incomeStorage.ts`)
*Утвержден и верифицирован задачей на ветке `task/storage-and-first-launch`.*
- **Ключ**: `@price2life/user_income_v1`
- **Схема**: `UserIncomeSettings { income: number; period: IncomePeriod; updatedAt: number; }`
- **Отказоустойчивость**: `validateAndParseIncomeSettings` перехватывает поврежденный JSON и некорректные типы, возвращая `null` без сбоя приложения.
- **Контекст**: `IncomeProvider` предоставляет состояние `isLoading`, `isConfigured`, `income`, `period`, `hourlyRate` и методы `saveIncome`, `resetIncome`.

### 4.5. Навигация и UX экранов (`src/screens/`)
*Утвержден и верифицирован прототипом на ветке `prototype/ui-screens`.*
- **Стек**:
  - `Converter` (главный экран):
    - Appbar с заголовком и кнопкой открытия настроек.
    - Карточка Hero Card с крупным отображением времени (`headlineLarge`) и общим числом рабочих часов. Hourly Rate на конвертере не показывается.
    - Поле ввода цены (outlined) с кнопкой очистки. Пресеты/чипы типовых цен отсутствуют.
  - `Settings` (модальный экран `presentation: 'modal'`):
    - Если `isFirstLaunch: true`: баннер первого входа, скрыта кнопка закрытия, перехват `BackHandler` на Android с алертом о необходимости сохранения дохода.
    - Поле дохода «на руки» (Net, целое число) без числового placeholder.
    - `SegmentedButtons` с выбором периода: Час, День, Нед., Месяц, Год.
    - Карточка превью часовой ставки в реальном времени.
    - Кнопка «Сохранить доход», вызывающая сохранение в AsyncStorage и закрытие модального окна.

## 5. Testing Decisions (Решения по тестированию)

### 5.1. Принципы тестирования
- Тестирование строго на **внешних швах поведения** (black-box), а не деталей реализации.
- Единый шов вычислений: чистые функции `calculateHourlyRate` и `calculateLifeTime` должны иметь 100% покрытие граничных случаев.
- Единый шов персистентности: `IncomeStorageService` тестируется через `InMemoryStorageDriver` без моков нативного Android.
- UI-тестирование: сквозной сценарий первого запуска (переход на настройки $\to$ валидация $\to$ сохранение $\to$ переход в конвертер $\to$ ввод цены $\to$ проверка отображаемого времени).

### 5.2. Модули для тестирования
1. **Калькулятор (`calculator.test.ts`)**:
   - Стандартный расчет месяца, недели, года, дня, часа.
   - Микропокупки (< 1 ч).
   - Покупка за 0.
   - Защита от переполнения часов при округлении (7.8 ч $\to$ 1 день, 0 часов).
   - Плюрализация часов (1 час, 2 часа, 5 часов, 21 час, 2080 часов).
2. **Хранилище (`incomeStorage.test.ts`)**:
   - Первый запуск (пустое хранилище $\to$ `isConfigured: false`).
   - Сохранение валидных настроек $\to$ `isConfigured: true`.
   - Отклонение невалидных данных (0, отрицательные, дроби).
   - Восстановление после поврежденного JSON.
3. **Компоненты экранов (`firstLaunchFlow.test.tsx`)**:
   - Автоматический модальный показ настроек при неинициализированном доходе.
   - Блокировка кнопки закрытия и нажатия аппаратного «Назад» на Android.
   - Успешное сохранение, расчёт Life Time Equivalent на конвертере, отсутствие Hourly Rate и чипов типовых цен на Converter.

## 6. Out of Scope (Вне рамок спецификации)

- Поддержка платформы iOS (сборка, стили и сертификаты настраиваются исключительно под Android).
- Мультивалютность и подключение внешних API курсов валют.
- Расчет налогов (Gross/Net калькулятор, вычеты НДФЛ).
- Поддержка дробных чисел (копеек/центов) в доходе и цене — решено использовать только целые положительные числа.
- Полный Expo Managed Workflow (используется Expo bare / CNG).
